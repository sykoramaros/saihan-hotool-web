# Saihan Hotool — Claude Code Instructions

## Project overview

React 19 SPA for a Mongolian yurt camp. Single-page app with hash-anchor navigation. All content comes from Payload CMS via GraphQL. Supports i18n (Czech/Mongolian) via LanguageProvider.

Built on the same base as `project_template` — Vite, TanStack Router (file-based), TypeScript, Tailwind CSS v4, shadcn/ui. `graphql-request` + `usePayloadQuery` are project-specific additions.

## Tech stack

- React 19, TanStack Router v1 (file-based, single `/` route)
- Tailwind CSS v4 + shadcn/ui (Radix UI primitives)
- `graphql-request` — GraphQL client for Payload CMS
- Payload CMS 3.x + SQLite (`@payloadcms/db-sqlite`) in `apps/cms/` — locales: cs/mn
- Vite 7, TypeScript (strict)
- lucide-react for icons
- No react-router-dom, no Bootstrap, no react-router-hash-link

## Hash navigation

All page sections are on `/`. Navbar links use JS scroll (not anchor hrefs):
- Home → scroll to top
- Info → `#info` (offset 80px for sticky navbar)
- Pricing → `#prices` (offset 80px)
- Gallery → `#carousel-gallery` (offset 80px)
- Contact → `#contacts` (footer wrapper)

## Custom CSS classes (defined in index.css)

- `.app-container` — animated gradient background (fixed, z-index: -999)
- `.carousel-container` — pill-shaped carousel with decorative box-shadow
- `.hide-scrollbar` — hides scrollbar on the horizontal price section
- `.language-container` / `.language-container.open` — floating circular language switcher
- `.cookies-modal-container` — fixed-position cookies banner
- `.modal-backdrop` / `.order-modal` — order modal overlay
- `.text-shadow-black` / `.text-shadow-white` — text shadow utilities

## Development

```bash
# Terminal 1 — CMS
bun run dev:cms      # Payload on :3000 (or whatever PAYLOAD_PORT is set to)

# Terminal 2 — frontend
bun run dev          # Vite on :5175
```

`routeTree.gen.ts` is regenerated automatically by the TanStack Router Vite plugin on every `dev`/`build`. Never edit it manually.

## Payload CMS — important notes

- **Array localization**: mark `localized: true` on the array field itself, NOT on individual fields inside the array. Each `updateGlobal({ locale })` call replaces the entire array — field-level localization within arrays causes data loss.
- **Re-seeding**: delete `apps/cms/data/cms.db`, restart CMS (`bun run dev:cms`), wait for migrations to run.
- CMS admin UI: `http://localhost:3000/admin`
- GraphQL playground: `http://localhost:3000/api/graphql-playground`
- Locales: `cs` (default) and `mn`

## Deployment

All services run via Docker Compose on a Mac Mini server (Colima).

```
Host:  mac-mini-server  (root@192.168.100.13)
Path:  /var/docker/saihan_hotool
```

Services:
- `caddy` — Caddy, port 80. Serves `apps/frontend/dist` via volume mount (no image rebuild needed for frontend changes).
- `cms` — Payload CMS (Node/Next.js), port `PAYLOAD_PORT`. Volume: `./apps/cms/data` (SQLite) and `./apps/cms/media`.

**When a full CMS restart is needed (down → pull → up → rebuild):**
- CMS source code changes (globals, collections, payload.config.ts)
- Changes to `docker-compose.yml` or CMS `Dockerfile`
- Dependency changes (`package.json`, `bun.lock`)
- Changes to `.env` or `apps/cms/.env`

**Frontend changes only (build locally + rsync, no container restart):**
- Any change to `apps/frontend/src/`
- Changes to `apps/frontend/package.json` or Vite config

**`git pull` only, no restart:**
- Documentation (`CLAUDE.md`, `README.md`)

### Deployment procedure

**Step 1 — Sync any server-side changes to git**

```bash
ssh mac-mini-server "cd /var/docker/saihan_hotool && git status"
# if there are uncommitted changes:
ssh mac-mini-server "cd /var/docker/saihan_hotool && git add -A && git commit -m 'chore: sync server-side changes' && git push"
```

**Step 2 — Apply any non-versioned file changes**

If `.env` or `apps/cms/.env` changed locally, apply the same changes on the server:

```bash
ssh mac-mini-server "nano /var/docker/saihan_hotool/.env"
ssh mac-mini-server "nano /var/docker/saihan_hotool/apps/cms/.env"
```

**Step 3 — Pull latest changes**

```bash
ssh mac-mini-server "cd /var/docker/saihan_hotool && git pull origin main"
```

**Step 4a — Frontend changed: build locally and rsync dist/**

```bash
cd apps/frontend && bun run build
rsync -avz --delete apps/frontend/dist/ mac-mini-server:/var/docker/saihan_hotool/apps/frontend/dist/
```

Caddy picks up the new files automatically via volume mount — no restart needed.

**Step 4b — CMS changed: rebuild and restart**

```bash
# CMS source changed (globals, collections, payload.config.ts, Dockerfile):
ssh mac-mini-server "cd /var/docker/saihan_hotool && /opt/homebrew/bin/docker-compose build --no-cache cms && /opt/homebrew/bin/docker-compose up -d"

# docker-compose.yml or infra config changed:
ssh mac-mini-server "cd /var/docker/saihan_hotool && /opt/homebrew/bin/docker-compose down && /opt/homebrew/bin/docker-compose up -d"
```

**Step 5 — Verify no errors in logs**

```bash
ssh mac-mini-server "cd /var/docker/saihan_hotool && /opt/homebrew/bin/docker-compose logs --tail 50"
```

Watch for `ERROR` lines. Use the full `/opt/homebrew/bin/docker-compose` path — SSH sessions do not load the user PATH.

**Step 6 — Follow live logs until all services are up**

```bash
ssh mac-mini-server "cd /var/docker/saihan_hotool && /opt/homebrew/bin/docker-compose logs -f"
```

Press Ctrl+C to stop following.

## Workflow

- Auto-commit and push after every file change (global CLAUDE.md rule applies).
- Commit message convention: `type: description` (feat, fix, chore, refactor, docs).
- Screenshots: save to `.playwright-mcp/`, never to project root. Take full-page screenshots at 375, 640, 768, 1024 px before and after any UI change. Delete all files in `.playwright-mcp/` after each commit.
- Do not commit `.env` or `apps/cms/.env` — they contain credentials.
- Do not commit `apps/frontend/dist/` or `apps/cms/data/` — both are gitignored.
- Remember: `.env` files are not versioned — if new environment variables are added locally, remind the user to apply the same changes manually on the server.
